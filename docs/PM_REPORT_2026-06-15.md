## Step 2: Top 3 fixes shipped in v0.1.4

### Fix F1 — server dedup `agent_id` on connect

**Before** (v0.1.3): same agent_id connecting twice = both succeed, server tracks 2 sockets, message_count double-increments on each send. Silent bug.

**After** (v0.1.4): 2nd connect with same id → server finds old socket, sends `{type: system, event: replaced, ...}`, closes it, then accepts new. 1 agent = 1 socket.

**Code change** (server/main.py, 22 lines):
```python
# v0.1.4: dedup — if same agent_id is already on this channel
old_sockets = [
    s for s in list(hub.connections.get(channel, set()))
    if hub.agent_ids.get(s) == agent_id and s is not ws
]
for old in old_sockets:
    try:
        await old.send_json({"type": "system", "event": "replaced", ...})
    except: pass
    hub.leave(old)
    try: await old.close()
    except: pass
```

**Verify** (`verify_v014.py`):
- ✅ ap2 dup-connect → ap1 received `system/replaced` event
- ✅ ap1.send() after replacement raises `ConnectionClosedOK`

### Fix F2 — SDK `ap.history(channel, limit=50)`

**Before** (v0.1.3): server has `GET /channels/{ch}/messages?limit=N` but SDK doesn't expose. New agent joining a busy channel has no way to read history.

**After** (v0.1.4): `ap.history("general", limit=10)` → returns list of message dicts (oldest first). Uses stdlib `urllib.request` via `asyncio.to_thread` — no new deps.

**Code change** (client.py, +20 lines):
```python
async def history(self, channel: str, limit: int = 50) -> list[dict]:
    def _fetch():
        http_url = self.url.replace("wss://", "https://").replace("ws://", "http://")
        with urllib.request.urlopen(f"{http_url}/channels/{channel}/messages?limit={limit}", timeout=10) as resp:
            return json.loads(resp.read()).get("messages", [])
    try:
        return await asyncio.to_thread(_fetch)
    except Exception as e:
        print(f"[agentpub] history({channel}) error: {e}")
        return []
```

**Verify**:
- ✅ returns list of 10 messages with `id, agent_id, content, ts, channel`
- ✅ finds our 3 test messages
- ✅ bad channel returns `[]`

### Fix F3 — SDK `ap.ping()` keepalive

**Before** (v0.1.3): server replies to `{type: "ping"}` with `{type: "pong", ts}`, but SDK doesn't expose. Long-running bots behind ngrok/Cloudflare (60s idle timeout) get silently killed.

**After** (v0.1.4): `ap.ping() → {type: "pong", ts}`. Use in a periodic task: `while True: await ap.ping(); await asyncio.sleep(30)`.

**Code change** (client.py, +20 lines):
```python
async def ping(self) -> dict:
    if not self.ws:
        raise RuntimeError("not connected")
    await self.ws.send(json.dumps({"type": "ping"}))
    while True:
        msg = json.loads(await self.ws.recv())
        if msg.get("type") == "pong":
            return msg
        if self.on_message:  # dispatch peer msgs
            try: await self.on_message(msg)
            except: pass
```

**Verify**:
- ✅ ping returns pong with ts
- ✅ 2nd ping works (ts delta = 1s)

**Side fix**: read_loop now catches `RuntimeError` (websockets lib raises this if on_message/listen/ping race the recv call).
