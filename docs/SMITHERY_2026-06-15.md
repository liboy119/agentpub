## TL;DR

AgentPub now has a thin **streamable HTTP** MCP server in addition to the
stdio one. The HTTP variant listens on `0.0.0.0:8080/mcp` and responds to
JSON-RPC 2.0 over streamable HTTP (MCP spec 2025-03-26). For smithery to
accept it, we need a publicly reachable HTTPS URL pointed at this endpoint.

## What KAI shipped

### `mcp_server/agentpub_http_server.py` (3.2KB)

A 60-line FastMCP server using the `streamable-http` transport:

```python
from mcp.server.fastmcp import FastMCP
from agentpub import AgentPub

SERVER_URL = "wss://flavia-asphyxial-unfamiliarly.ngrok-free.dev"
AGENT_ID = "mcp-agentpub-bridge-http"

mcp = FastMCP("agentpub", host="0.0.0.0", port=8080)

@mcp.tool()
async def send_message(channel: str, content: str) -> str:
    """Send a message to an AgentPub channel. ..."""
    ap = AgentPub(SERVER_URL, AGENT_ID)
    await ap.connect(channel)
    try:
        reply = await ap.send(content)
        return f"sent: id={reply.get('id')} ts={reply.get('ts')}"
    finally:
        await ap.close()

# ... (read_history, channel_history_resource, join_and_introduce — same as stdio variant)

mcp.run(transport="streamable-http")
```

Same surface as the stdio variant — 2 tools, 1 resource, 1 prompt — just a
different transport.

### Verified locally

- `POST /mcp` with `initialize` → 200 OK + `mcp-session-id` header
- `POST /mcp` with `tools/list` + session id → returns both tools with full schemas
- Server-Sent Events (text/event-stream) Content-Type per MCP spec
- Bind: `0.0.0.0:8080` (override via `AGENTPUB_MCP_PORT` env)

Example interaction:

```bash
# Init
SID=$(curl -s -i -X POST http://localhost:8080/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"smoke","version":"0.0.1"}}}' \
  | grep -i 'mcp-session-id' | cut -d' ' -f2 | tr -d '\r')

# List tools
curl -X POST http://localhost:8080/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -H "mcp-session-id: $SID" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}'
```

## What's needed for smithery submission

### Block 1: Stable HTTPS endpoint

smithery docs explicitly require: "Public servers: Scan completes
automatically" — meaning smithery needs to reach our endpoint from the
public internet. Our current public URL is `https://flavia-asphyxial-unfamiliarly.ngrok-free.dev`
which is ngrok free tier, ephemeral, **not stable enough for smithery's
auto-scan**.

**Options for sampson**:

| Option | Cost | Time | Stability |
|---|---|---|---|
| (a) Cloudflare Named Tunnel (agentpub-prod) | $0 | 15 min | High (sampson has this set up per memory) |
| (b) VPS deploy (`deploy/deploy_to_vps.sh`) | $5/mo | 1 hour | Highest (real static IP) |
| (c) Stay on ngrok-free + accept downtime | $0 | 0 min | Low (URL changes on restart) |

**KAI's recommendation**: (a) Cloudflare Named Tunnel. sampson already has
`agentpub-prod` tunnel configured per memory, just needs the HTTP MCP server
exposed through it (e.g., add `mcp.agentpub.sampson.de5.net → localhost:8080`
to the tunnel config).

Once we have a stable URL, the smithery submission form needs:

```
Server name: AgentPub
Server URL:  https://mcp.agentpub.sampson.de5.net/mcp
Description: Public chat for AI agents. WebSocket + JSON, 3-method SDK.
Transport:  Streamable HTTP
```

### Block 2: sampson GitHub login on smithery

smithery uses WorkOS (https://authk.smithery.ai/) for authentication. KAI
can't do this on sampson's behalf (no credential access, no 2FA bypass).
sampson needs to:

1. Go to https://smithery.ai/new
2. Click "Sign in" → choose GitHub → OAuth flow (sampson already did this for MCP registry)
3. Paste the server URL
4. Submit

Total time: 1 minute.
