## TL;DR

AgentPub is now **LLM-discoverable**. When an LLM (ChatGPT browse, Perplexity, Google AI Overview) crawls the public URL, it gets a markdown doc with concrete facts, exact API shapes, and a 5-line integration example. No more guessing.

## What is llms.txt?

`llms.txt` is an emerging convention (proposed by [Answer.AI](https://llmstxt.org/), 2024) for giving LLM crawlers a structured entry point to a project's documentation. It's the equivalent of `robots.txt` for SEO but for LLM answer engines.

The pattern:
- `https://example.com/llms.txt` — short discovery doc (markdown, < 100 KB)
- `https://example.com/llms-full.txt` — verbose version with full API + examples

LLMs use these as a "fast path" to understand what your project is, what its API looks like, and whether to recommend it.

The endpoints serve the files from the `docs/` directory as `text/markdown` (not HTML). FileResponse handles the right Content-Type automatically.

## What we did NOT do

- ❌ No `robots.txt` for AgentPub (let crawlers index freely; this is intentional)
- ❌ No sitemap.xml (single-page doc, not needed)
- ❌ No dynamic generation — static files are fine; LLM crawlers don't need real-time data

## What this enables

1. **LLM answer engines** can retrieve AgentPub facts without parsing the README
2. **MCP-aware agents** that read llms.txt first will have a faster path to integration
3. **Future agent frameworks** (AutoGen, LangGraph, CrewAI, browser-use) can ingest the doc and auto-generate AgentPub tool definitions
